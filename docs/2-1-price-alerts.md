# ATELIER 2-1 · 일간 급등락 감지 설계 및 구현 착수

## 사용자 경험: 새 메뉴 없이 발견 → 원문 확인

- **전체 현황:** 가장 이례적인 급등락을 최대 3건만 노출. 당일 종가의 ±8% 이상과 최근 20거래일 변동 폭 대비 2배 이상을 모두 충족해야 후보로 선정. 기준값은 초기 가설이며, 바이오·대형 소비재 등 업종별 오탐률을 검증해 조정.
- **기업 분석:** 같은 이벤트의 기준 거래일, 일간 변동률, 거래량·업종 대비 움직임(확인된 경우만), SEC·기업 IR·임상·검증 뉴스 원문을 펼쳐보기로 제공.
- **원인:** 관련 사건이 같은 기간에 확인돼도 **원인으로 확정하지 않음**. `공식 사건 동기간 확인 · 인과 미확정`, `관련 뉴스 동기간 확인 · 인과 미확정`, `원인 미확인`의 단계만 사용.
- 이메일·푸시 알림은 만들지 않고 사이트 내부 표시부터 시작.

## 구현된 첫 부분

- `scripts/price_events.py`는 시세 공급과 분리된 **순수 감지 엔진**. 동일 종목·같은 거래일 중복, 과거 거래일과 당일 거래일 혼합, 조정되지 않은 주가로 인한 액면분할 오탐, 업종 ETF와 날짜 불일치, 공식 원문과 주가 인과관계의 잘못된 확정을 방지.
- `tests/test_price_events.py`의 가격·원문은 모두 **가상 테스트 데이터**이며 실제 종목의 수익률, 급등락 또는 실시간 알림이 아님.
- 신뢰할 수 있는 일간 종가 데이터 및 그 파생 수익률을 공개할 수 있다는 별도 허가가 확인되지 않은 경우 감지 엔진은 **빈 목록**과 `permission_required`를 반환. `TWELVEDATA_API_KEY` 보유만으로 재배포 권한이 증명되지는 않음.
- 기업 목록은 기존 `research-universe.json`의 `US:` 고유 ID를 사용. 미래 국내 종목 적용 시 해당 시장의 거래일 달력과 별도 공급 계약부터 확인.

## 입력 데이터 계약 (다음 통합 단계)

적법한 공급원으로부터 동일 제공사·같은 거래일 기준으로 검증된 입력만 전달해야 함.

- `issuerId, ticker, tradeDate, previousTradeDate`: 모두 명시. 영업일을 임의 추론하지 않음.
- `close, previousClose`: 분할 조정 종가, `priceBasis=split_adjusted_close`. 배당 포함 총수익률과 섞지 않음.
- `volatility20dPct`: 검증된 20거래일 기준 평균 변동 폭(%) 등 정의가 동일한 과거 변동성 지표. 0이거나 정의가 없으면 감지하지 않음.
- `volume, averageVolume20d`: 있을 경우에만 거래량 급증 표시.
- `sectorReturnPct, sectorTradeDate`: 있을 경우 날짜 일치 시에만 초과수익률 산출.
- `source.provider, source.url`: 데이터 공급자와 원문 출처. 재배포·파생 데이터 사용 조건 확인 후만 공개.
- 사건 근거는 `issuerId, sourceType, verified, publishedAt, title, url`. 원문 발행일이 해당 거래일 또는 최대 이틀 전인지 확인. 단순 동시성으로 인과를 주장하지 않음.

## 다음 작업

1. 시세 공급자의 **일간 종가·거래량 제공 / 공개 웹사이트 숫자 게시 / 파생 변동률 기록 / Git 공개 저장소 및 이전 빌드 보관** 허용 조건 확인.
2. 승인된 공급 데이터를 내부 전용 수집 결과로 표준화하고, 입력 라이선스를 명시적으로 검증하는 변환 계층 도입. 주가 숫자가 없는 현재는 이벤트를 허구로 채우지 않음.
3. 기업 공시·기업 IR·ClinicalTrials.gov·검증 뉴스 목록을 거래일 기준으로 연관시키고, 사용자 화면 상위 3건과 기업 상세에 연결.
4. 소규모 실제 데이터 관찰 기간 동안 바이오 업종의 오탐률과 기준값을 검토한 뒤 표시 기준 확정.

**범위:** 현재 단계는 감지 로직·인과관계 방지·테스트 착수이며, 실시간 감지나 시세·알림 운영 개시가 아니다.
